2. User flow

  1. Open / → intro plays once per session (dot grows, becomes the full stop, the word is drawn out) → catalog fades up below.
  2. Type in Search → after the debounce, the URL becomes ?q=cream → skeleton grid → results + live count "3 products for “cream”".
  3. Pick a Category (works together with search) → ?q=cream&category=beauty → page resets to 1.
  4. Pick Sort → &sort=price&order=asc → grid reorders (no page reset needed, but it does go back to page 1).
  5. Click a page number → &page=2 → scroll to the products heading, focus it.
  6. No match → Empty state → "Clear filters" → back to all products. Network fails → Error state → "Try again" → loading → results.
  7. Click a product card → view transition (old page fades, new page rises with a curtain, the image morphs) → /product/12 → detail skeleton → detail.
  8. On detail: pick a thumbnail → main image swaps. Scroll to Reviews. "← Back to catalog" → returns to the exact same filters and page (href keeps the query string).
  9. Bad id (/product/abc or 404) → Product not found → "Back to catalog".

3. Home with intro animation

Live: plays on page load; press Replay to watch again. Timeline ≈ 2.6s: dot appears and swells (0.2–0.7s) → shrinks to full-stop size (to 1.4s) → glides right while the letters are uncovered to its left (1.0–2.4s) → tagline, toolbar and grid fade up (from 2.0s) → small header wordmark fades in last. Nothing blocks clicks while it plays.

12. Page transition (catalog ↔ detail)

Click a card (or use the tabs) to "navigate". The header stays still; the new page rises in behind a curtain (clip-path: inset(100% 0 0 0) → inset(0), 900ms soft ease) and the product image grows from the card's position. In the real app the browser's View Transitions API also fades the old page out (350ms) and morphs the exact card image into the detail image; this static file can only imitate that. Under reduced motion, pages swap instantly.
